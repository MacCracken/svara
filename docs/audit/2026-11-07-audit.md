# svara — 2026-11-07 P(-1) sweep (audit, hardening, refactor, optimization)

> **Status**: the 3.6.3 deliverable. The sweep ran six cluster audits against the
> compiled Rust oracle, a real fuzz target, fault injection, an all-zero argument
> sweep, execution coverage, and an independent review of the merged diff.
> **39 findings: 30 repaired with tests, each shown to fail without its fix; 8
> recorded in [ADR-0009](../adr/0009-what-the-3-6-3-audit-leaves-open.md); 1
> upstream.** The repairs are 1 P0, 4 P1, 13 P2 and 12 P3. The independent review
> also caught a P0 that the sweep's own work had introduced, fixed before release.
> Audio on valid input did not move: 558,721 values were compared against 3.6.2.
> Predecessor: the 3.1.3 adversarial-input sweep, recorded in
> [ADR-0001](../adr/0001-signed-index-and-float-conversion-hazards.md).

## 1. Why this audit

svara's last audit was 3.1.3. Since then the port has had a run of toolchain bumps,
state companions for every engine type (3.3.0), and NaN rejection (3.5.2). It had
never been run against the compiled oracle, and it had never had a fault injected.
Its fuzz target was still the scaffold stub, which could not fail. 3.7.0 removes
`rust-old/`, so this was the last release where a differential could run.

naad's sweep fixed 45 defects that none of its 2,418 assertions had caught, so a
passing suite was no reason to expect a clean result.

## 2. Method

| Lens | What it did | Size |
|---|---|---|
| Cluster audits | Six readers each took one cluster: source (glottal, rng, smooth), filter (formant, tract, lod), phoneme, speech (prosody, trajectory, voice), render (sequence, pool, render) and boundary (error, logging, spectral, bridge). Each read its code line by line against `git show 3.5.2:rust-old/src/…` and reproduced every finding with a probe on both sides. A finding without a reproduction was dropped. | 17 modules, 290 public fns |
| Differential | The oracle was built in a scratch copy (`cargo --release --offline`). Each probe drove the same inputs through both sides, comparing outcome class and value: hostile values for each numeric parameter, plus realistic input. | per-cluster grids, e.g. 2,860 spectral lines |
| Fuzz | `tests/svara.fcyr` rewritten from the stub: 15 groups over every public entry, forked batches so one fault cannot hide the rest, and a replay mode (`./fz <case>`). The JSON group mutates documents only in ways a well-formed writer could produce (number swaps, and key drops on state types), as ADR-0002 scopes the contract. Each JSON case then damages 8 more documents byte by byte and decodes only what `svara_validate_json` accepts. | 2,400 cases per run; 24,000 in 11 s |
| Fault injection | A scratch tree with no manifest and a patched `lib/alloc.cyr` refuses the Nth allocation, once or from then on, across 14 pipelines. Each run is hashed against an unpatched baseline and classified as silent wrong answer, refused, fault or hang. Fault addresses come from gdb's `$_siginfo._sifields._sigfault.si_addr`. | 3,050 cases during the sweep; 2,056 on the release tree |
| All-zero sweep | Every public function called with every argument 0, which is what a lenient decoder hands back for a missing field. Logging is left out, as it builds only under `-D LOGGING`. | 290 fns |
| Execution coverage | `cyrius coverage --exec` names the functions no suite enters. | 255/290 at the start, 273/307 at the end |
| Mutation proofs | Every fix's test was run against the code with the fix reverted, and it had to fail. | every repair below |
| Independent review | A reader who saw none of the work reviewed the merged diff against tag 3.6.2 and the oracle. | § 6 |

## 3. What the sweep did not find

- **No fault on valid input in the synthesis path.** Every finding that touches
  audio on valid input is a wrong-state or ownership defect (§ 4), not a crash.
- **No fault away from the null page.** Under fault injection on the release tree,
  all 1,840 faults were at `si_addr` 0x10 or less, and so were all 2,834 in the run
  before the optimizations. Under the all-zero sweep, 184 of 290 functions faulted,
  all at 0xb0 or less. A null-page fault is a fail-stop on Linux. Neither run found a
  wild address.
- **No hang** in either run, after the RN-1 fix.
- **No regression of the 3.1.3 repairs.** `tests/hardening.tcyr`'s original ten
  probes still pass.
- **Every bridge map matches the oracle.** All 19 maps in `src/bridge.cyr` were
  compared on a grid that included NaN, ±inf and out-of-range values: 3,980
  lines, none differing beyond f32 precision.

## 4. Findings repaired

Severity: **P0** memory-unsafe, or an abort or hang on valid input. **P1** wrong
result on valid input. **P2** abort, hang or wrong result on hostile input. **P3**
minor.

### P0

- **RN-1. A batch renderer extended from its own saved state never finished.**
  `svara_batch_save` stored the live queue vec, so `svara_batch_extend(r, save(r))`
  walked a vec it was appending to, until the capacity overflowed past 2 GiB. Save,
  restore and extend now copy, and extend captures its length first.

### P1

- **PH-1, RN-2. A restored context, pool or batch renderer did not resume.** Their
  states dropped the glottal and tract state, and the header claimed they held
  nothing between calls. A restored object differed from the original on every
  voiced phoneme. The suite had checked /s/ only, which is unvoiced. The three
  states now carry `glottal` and `tract` vecs and resume bit-exactly. A 3.6.2
  document has neither field and still restores, starting fresh as before.
- **AF-F1. Retargeting a tract left stale upper formants.** `set_vowel` and
  `set_formants_from_target` wrote five formants into the tract's record in place.
  A record of six to eight formants kept slots 6–8, and the bank went on ringing at
  formants the new vowel does not have.
- **BD-1. `svara_spectrum_estimate_formants` returned a different formant set on
  magnitude ties.** Its selection sort was not stable, and Rust's `sort_by` is.
  Both passes now share a stable bottom-up merge sort.
- **RN-3. Objects kept the caller's pointers.** `svara_sequence_push`,
  `svara_batch_extend`, `svara_batch_save` and `svara_batch_restore`, and
  `svara_render_output_save` and `_restore` all kept vecs or events the caller still
  owned. Two restores from one state shared a queue. Rust moves or clones in every
  one of these places. Each now copies at the boundary, as naad's ADR-0005 does.

### P2

- **FZ1. `svara_formant_bank_update` wrote through an unbounded slot index**, a
  wild write. It now returns `SVARA_ERR_INVALID_FORMANT` outside `[0, 8)`.
- **FZ2. `svara_trajectory_plan` with phoneme and duration vecs of different
  length** aborted when durations was shorter and ignored the extras when longer.
  Rust asserts. svara now returns `SVARA_ERR_INVALID_DURATION`.
- **FZ5. `svara_pool_render_batch` with parallel vecs of different length**
  aborted in `vec_get`. It now returns `SVARA_ERR_INVALID_DURATION`.
- **AS-F1. Every `*_restore` faulted on a null state**, which is what a decoder
  returns for a malformed document. Trajectory restore also faulted on null
  keypoints. Every restore now refuses a null state, a missing vec field and an
  out-of-range enum.
- **AF-F2. A rejected `set_formants_from_target` still wrote its target into the
  record**, so a later save captured formants the filter did not have, and restore
  refused it. The target is now validated in scratch before the record changes.
- **BD-2. `svara_spectrum_estimate_formants` was O(n²).** A 2²⁰-sample noise frame
  took 23,424 ms where Rust takes 6 ms. It now takes 45 ms and returns the same
  formants.
- **BD-3. Spectral queries allocated scratch on every call and never freed it.**
  `svara_spectral_rms_level` used 8 KB per call, which is 1.27 GB per hour of
  metering. When the arena ran out it returned 0.0, a plausible value. Scratch is
  now grow-only, and a refused growth ends the process.
- **FI-1. `svara_prosody_f0_at` returned 1.0 when an allocation was refused**,
  one of eight silent wrong answers under fault injection. It now ends the
  process, and so do the other seven (spectral scratch, under BD-3).
- **RN-4. The progress callback's return value was treated as an error code.** In
  Rust the callback returns `()`. A callback that happened to return a negative
  value stopped the render. The return value is now ignored.
- **RN-6. Concatenated output past `SV_MAX_SAMPLES` aborted in `vec_push`**, even
  though each segment was under the cap. `svara_seq_crossfade`, `render_batch` and
  `render_with_progress` now check the running total and return
  `SVARA_ERR_COMPUTATION`.
- **PH-5. An invalid phoneme id rendered as something.** `phoneme_class` had no
  lower bound, so id -1 rendered as a vowel, and id 101 counted as voiced. A
  decoded sequence can carry any integer. Invalid ids are now class SILENCE, not
  voiced, and return `SVARA_ERR_INVALID_PHONEME` from every synthesis entry and
  from `render_planned`.
- **RV-2. `svara_formant_filter_update` took a non-finite formant.** ADR-0007's
  refusal lived only in `svara_formant_validate`, which `new` and `rebuild` call and
  `update` does not, so an infinite bandwidth or NaN frequency went into a live bank
  and every later sample was NaN. Found by the independent review. Rust's
  `update_formants` validates nothing, so only the non-finite check is added.
- **RV-3. `svara_batch_restore` accepted out-of-range event enums.** Stress 7
  restored and rendered as unstressed. It now refuses an event whose phoneme, stress
  or tone is outside its enum. Found by the independent review.

### P3

- **AF-F3.** `svara_tract_set_nasal_place` recorded a place naad had refused, so a
  save and restore changed the notch. The place is now recorded only on success.
- **AF-F5.** An infinite bandwidth was accepted, contrary to ADR-0007's text. It is
  now refused.
- **AF-F6, AS-F2.** Restores and setters accepted an out-of-range quality, nasal
  place, glottal model (model 7 acted as LF) or diplophonia phase (2 disabled it).
  Restore now refuses these, and the setters ignore them.
- **AS-F3.** A non-finite vibrato rate restored as an LFO at a different rate.
  Restore now refuses it (ADR-0009).
- **SP-2.** `svara_prosody_make` kept the caller's points vec, so two contours built
  from one vec aliased. It now copies.
- **SP-3.** `svara_trajectory_formants_at` on a one-keypoint plan returned the
  keypoint's own target, and the caller could mutate the plan through it.
- **SP-4.** Contour points were ordered by an unstable selection sort, and Rust's
  `sort_by` is stable. It is now a stable insertion sort.
- **BD-5.** `SVARA_LOG` level names were case-sensitive, so `OFF` turned logging
  on. They now match case-insensitively.
- **BD-6.** The spectral header and ADR-0002 both said `Spectrum` does not
  serialize. It does.
- **BD-8.** Ten of the Rust integration tests were unported and six were partial.
  `tests/integration.tcyr` ports all 16, with 26 assertions.
- **PH-4.** `svara_ph_apply_envelope` guarded `n == 0` but not a negative `n`.
  This was unreachable from the entry points, and it is now guarded.

### Upstream: the cyrius `#derive(Serialize)` decoder (FZ4)

The fuzz target's first, unrestricted JSON group found two failures. Only one of them
is upstream.

**Case 82 hangs, in compiler-generated code.** `SvProsodyContour_from_json_str` never
returns on this 162-byte mutated contour (killed at 10 s), written as a Python bytes
literal:

```
b'{"f0_points":[\x1a"time":0.0,"value":0.85},{"time":0.3,"value":0.85},{"time":0v7\xdc"value":1@1},{"time":1.0,"value":1.25}],"duration_scale":1.`,"amplitude_s(ale":1.0}\n'
```

The decoder is emitted by the cyrius compiler (`src/frontend/lex/pp/serialize.cyr:514`
at 6.7.18), and bayan is not involved. Its `Vec<struct>` element loop sends any byte
other than `{` to `_cy_json_skipval`, which returns without moving at a depth-0 `}`, so
the loop meets the same `}` forever. Here the first element has lost its `{`: the skip
walks `"time":0.0` to the comma, then `"value":0.85` to the `}`, and stops there. The
smallest trigger is `[}]`.

Every svara type with a vec of structs inherits it, including five state companions.
`SvVocalTractState_from_json_str` and `SvBatchRendererState_from_json_str` both hang on
a `[}]` vec (killed by SIGALRM), before `restore` can see the state. So `restore`, the
validated entry, does not protect a caller from this.

**svara's guard.** svara cannot change the generated decoder, but it can check the text
first. `svara_validate_json(doc)` accepts only what svara's writer produces: one
object of objects, arrays, numbers and `null`, `true` or `false`; keys of letters,
digits and `_`; no string value, no escape, no whitespace inside the object;
brackets that close their own kind; nesting to 16 levels; numbers to 32 bytes. The
limits were measured: the suite's 25 documents nest at most 5 deep, and the
writer's longest number is 24 bytes (`-1.7976931348623157e+308`). Two decoder
quirks set the rest. It ends a key at the first `"` whether or not it is escaped,
and it skips only spaces between a key and its value.

The decoder's view and the real structure line up on a document that passes, so
neither defect can be reached. That rests on reading the decoder, so it was
measured too. A scratch probe damaged 70,000 documents of the seven affected types
with 1 to 4 edits each: an inserted or overwritten hostile byte, a deleted byte, or a
cut. Each document was decoded in its own forked child under a 300 ms timer:

| | documents | refused | decoded | hung | faulted |
|---|---|---|---|---|---|
| with the check | 70,000 | 63,821 | 6,179 | **0** | 0 |
| without the check | 7,000 | 0 | 6,697 | **303** | 0 |

All 303 hangs were the stray-brace defect. In the suites, `tests/serde.tcyr` checks
that every document it writes passes, and `tests/hardening.tcyr` holds 24 refusal
rows. Seven mutations each loosen one rule, and each fails only the rows aimed at
that rule. Removing the whole check fails 23 of the 24; the null-pointer row is kept
by the guard in front of it. The fuzz target damages 8 documents per JSON case
and decodes only what the check accepts, and with the check removed the fuzz run
fails.

It is filed in the local cyrius repo as
`docs/development/issues/2026-11-07-derive-serialize-vec-struct-element-loop-hangs-on-stray-brace.md`.
Its repro forks a child per row under `alarm(2)` and exits 3 on 6.6.0, 6.6.20, 6.7.9 and
6.7.18. The proposed fix gives the loop the forward-progress guard that the
`Vec<int>` helper already has. It has not been built into a compiler.

**Case 33 is svara's own gap.** The mutation mangled the `events` key of a phoneme
sequence, so the decoder left the vec at 0, and the harness faulted on `vec_len(0)`.
That is FZ3, the direct-decoding gap recorded in ADR-0009.

**A wrong first attribution.** The first minimization blamed bayan, on
`bayan_json_v_parse("xxx\":0.5}")` segfaulting at address 0. That repro was a misuse:
`bayan_json_v_parse` takes a `Str`, and it was handed a C string, so `str_data` read the
bytes `xxx":0.5` as a pointer. The pointer is not canonical, and the kernel reports that
kind of fault as address 0. Re-checked before filing, and nothing found here is a bayan
defect. Lesson: a minimized repro must still call the API as documented.

The fuzz target's JSON group now keeps to documents a well-formed writer can produce.

## 6. Independent review

A reader who saw none of the work reviewed the merged diff against tag 3.6.2 and the
oracle. It was given the diff and the stated intent of each change, not the audit's
conclusions, and it reproduced every finding with a probe.

| ID | Severity | Finding | Outcome |
|---|---|---|---|
| RV-1 | P0 | `estimate_formants` ended the process on a valid spectrum. The new grow-only peak scratch was sized by bin count and capped at 2²⁶, and `analyze` returns up to 2²⁶+1 bins. 3.6.2 returned one formant for such a spectrum. | Fixed before release. At most half the bins can be peaks, so each array is now `bins/2 + 1`. The reviewer's probe now returns 1 formant, and the suite pins the size. This was in the sweep's own work and never shipped. |
| RV-2 | P2 | `update` took a non-finite formant | Fixed (§ 4) |
| RV-3 | P2 | batch restore took out-of-range event enums | Fixed (§ 4) |
| RV-4 | P2 | an explicit `null` reads as an empty list | Recorded (§ 5) |
| RV-5 | P3 | the envelope test's "below the buffer" assertion could not fail: with `n = -5`, 3.6.2 writes slot 2, not slot 0 | Fixed: the test checks all ten slots |
| RV-6 | P3 | an infinite base f0 returns -1 where Rust returns -5 | Already recorded as BD-7 |

It found the sweep's other claims clean, and checked each by probe:

- The optimizations are bit-identical: 558,721 values.
- A context restored from JSON continues bit-exactly on 303 of 303 warm-ups, and
  batch and pool are exact too.
- 3.6.2 and empty documents restore.
- The merge sort matches a reference stable sort on 3,000 tie-heavy spectra.
- The ownership copies carry every field, and the module scratch is never
  re-entered or adopted.
- No new `vec_get` sits behind a non-short-circuit `&` or `|`.

The review's lesson for the next sweep is that the audit's own repairs need the same
scrutiny as the code it audited. RV-1 is a fail-stop added for safety that fired
on valid input, because its size bound was taken from the wrong quantity. One
assertion added in response to the review also turned out not to discriminate: it
passed with its fix reverted. It was moved, and it now fails without the fix.

## 7. Refactor and optimization

The bar for every change in this section was bit-identical output. Each was checked
with `scripts/sweep/compare.py --old-tree` against a snapshot taken before the
section began.

| Change | Measured |
|---|---|
| Diphthong loops use one scratch target and `_interpolate_into` instead of allocating 80 B per sample | context diphthong, 1 s: 3,881,120 → 353,200 B; nasalized: 4,931,424 → 1,403,480 B |
| `svara_formant_filter_rebuild` zeroes only the slots past `n` | render_planned −2.8% instructions, toned −2.35%; cycles flat |
| `_into` forms back `interpolate`, `to_formants`, `formants_at` and `catmull_rom_vowel`, instead of duplicating them | one body each |
| `svara_glottal_apply_rd` uses a module scratch | 24 B fewer per `new`, `set_rd` and `set_creaky` |
| `svara_smooth_new` delegates to `svara_smooth_with_time` | one body |
| `estimate_formants`: merge sort, grow-only scratch | 23,424 ms → 45 ms on a 2²⁰ frame |
| `tests/svara.bcyr`, the scaffold benchmark stub | deleted; `benches/` holds the real ones |

**One repair costs speed, and the optimizations did not pay for it.** Against 3.6.2,
`render_planned` retires 3.1% more instructions and a toned render 2.6% more. Cycles
rise by about the same. Every other probe is within 0.01%. The AF-F1 and AF-F2 fix
accounts for 4.3 points of that: `set_formants_from_target` now builds the target in
scratch, so a rejected one never reaches the tract's record, and then copies it into
the record on every sample. This was measured against a variant with the old
write-in-place path. Validating the target before writing in place would keep the
fix and drop the copy. It is roadmap 3.8.x, because it changes a per-sample path.

The larger refactors the audit found were left for roadmap 3.8.x, because each
changes the shape of a hot loop and needs its own measurement:

- `render_planned` recomputes per-event values on every sample.
- `f0_at` refills its scratch on every call.
- The one-shot and context synthesis paths duplicate each class.
- There are 13 copies of `approx` in the tests.
- A voice is cloned per event.
- naad's block forms are not called.
